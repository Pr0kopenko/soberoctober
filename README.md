# Sober October

Русский mobile-first сайт про 31 день без алкоголя. Калькулятор, личный календарь, Bingo 5×5, скачиваемая PNG-карточка и материалы без обещаний медицинских эффектов.

**Основной адрес:** https://soberoctober.ru  
**Репозиторий:** https://github.com/Pr0kopenko/soberoctober  
**Предпросмотр:** https://pr0kopenko.github.io/soberoctober/

## Стек и стоимость

Статический HTML + CSS + ES modules. Node.js нужен только для сборки и локального запуска. Основной сайт не требует npm-зависимостей, backend, базы данных, внешних шрифтов или платных API. Общая стена отдельно использует Cloudflare Workers, D1 и Turnstile; личный дневник работает без сервера. React/Next.js здесь не нужны: все страницы заранее отрисованы для SEO, взаимодействия небольшие и работают на устройстве. Готовую папку `dist` можно разместить на любом статическом хостинге. Условия бесплатных тарифов хостингов могут меняться.

## Запустить локально

Нужен Node.js 24+ (в том числе для тестов сервиса стены; CI использует 24). Установка зависимостей не требуется.

```sh
git clone https://github.com/Pr0kopenko/soberoctober.git
cd soberoctober
npm run dev
```

Открыть http://127.0.0.1:4173. После правки исходников повторить `npm run build` и обновить страницу; сервер `npm run preview` обслуживает готовую сборку без пересборки. Остановка — Ctrl+C. Не открывайте HTML через `file://`: модули и localStorage требуют обычного HTTP-сайта.

```sh
npm test
npm run build
npm run check
npm run preview
```

`npm test` проверяет формулы, границы дат, високосный год, валидацию хранилища, подсчёт отметок и линии Bingo. `npm run check` проверяет все страницы, локальные ссылки и ресурсы, JSON-LD, метаданные, H1, sitemap и размер OpenGraph-картинки.

## Как считается прогресс

Номер дня — место сегодняшней даты в 31-дневном календаре. Итоги и карточки используют **только подтверждённые пользователем даты**, включая сегодня, если он отметил этот день. Это количество дней, не непрерывная серия. Пропуски не стирают достижения.

Дата старта включается в 31 день: 5 октября → 4 ноября. Можно выбрать прошлое или будущее. При старте задним числом можно явно подтвердить все прошлые дни; по умолчанию флажок выключен. Будущие даты нельзя отмечать. После 31 дня итоги остаются доступны.

Формула: `вечеров в неделю × порций за вечер × отмеченных дней / 7`. Деньги — умножение на цену порции. Калории — умножение на объём / 100 и ккал на 100 мл. Прогноз калькулятора использует 31 день. Оценки усреднённые, без расходов на замену и без прогноза веса. Калорийность по умолчанию — редактируемое допущение, предпочтительны данные с упаковки.

Изменение чисел пересчитывает старые отметки. Изменение даты старта сбрасывает календарь, но сохраняет Bingo; интерфейс предупреждает об этом. Удаление всех данных требует подтверждения в диалоге.

## Хранение и приватность

Ключи: `sober-october:v1`, `sober-bingo:v1`, `sober-consent:v1`. Персональные параметры не уходят в API и не передаются в Метрику. Резервной копии и синхронизации нет: другой браузер, другой домен или очистка хранилища — другой прогресс. В частности, отметки с GitHub Pages автоматически не перейдут на `.ru`.

При запрете localStorage появляется сообщение, а форма не переходит на календарь, пока данные нельзя сохранить. Повреждённый или несовместимый JSON игнорируется. PNG создаётся локально в Canvas, без сервисов генерации и сетевых загрузок. Web Share используется только при поддержке браузером, скачивание PNG остаётся доступно.

## Основной домен soberoctober.ru

1. Верифицировать домен в настройках GitHub Pages аккаунта через предложенную TXT-запись. Не удалять её после проверки.
2. В DNS регистратора настроить apex `.ru` на GitHub Pages по [актуальной инструкции GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Использовать адреса из документации на момент настройки; не переносить случайные IP из старых руководств. Для `www` — CNAME на `pr0kopenko.github.io`, если нужен этот алиас.
3. В **Settings → Pages → Custom domain** указать `soberoctober.ru`, дождаться проверки DNS и сертификата. Включить **Enforce HTTPS**, когда станет доступно.
4. В **Settings → Secrets and variables → Actions → Variables** добавить `SITE_DOMAIN=soberoctober.ru`. Это публичная настройка, не секрет.
5. Повторно запустить workflow. Сборка переключится на `/`, добавит `CNAME`, снимет `noindex` и разрешит индексацию.
6. Проверить HTTPS, прямой вход на `/calculator/`, скачивание карточки, canonical, `/robots.txt`, `/sitemap.xml` и `/og.png`. Добавить sitemap в Яндекс Вебмастер и другие нужные поисковые системы.

Не включайте `.ru` в переменной до подключения домена: сборка с корневыми путями не предназначена для предпросмотра в `/soberoctober/`.

### Если домены куплены в REG.RU

Проверено по документации 5 октября 2026. Сначала проверьте текущие NS домена: следующие действия относятся к `ns1.reg.ru` / `ns2.reg.ru`. При других NS менять записи нужно у соответствующего DNS-провайдера.

В REG.RU: **Домены → soberoctober.ru → DNS-серверы и управление зоной → Изменить → Добавить запись**. Для каждой строки создайте отдельную запись; TTL можно оставить стандартным. [Инструкция REG.RU](https://help.reg.ru/support/dns-servery-i-nastroyka-zony/nastroyka-resursnykh-zapisey-dns/nastroyka-resursnykh-zapisey-v-lichnom-kabinete).

| Тип | Subdomain | Значение |
| --- | --- | --- |
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | pr0kopenko.github.io |

Это адреса из [документации GitHub Pages](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). В CNAME не добавляйте `/soberoctober`. Старые A/AAAA для парковки заменяются; почтовые MX/TXT и проверочную TXT-запись GitHub сохраняйте. Затем выполните настройку Custom domain, HTTPS и SITE_DOMAIN выше. Изменения DNS и выпуск сертификата могут занять до суток.

Для `.online` используйте уже имеющийся Cloudflare: добавьте этот домен, перенесите необходимые существующие DNS-записи и в REG.RU замените NS **только этого домена** на пару, которую покажет Cloudflare. После статуса Active настройте правило 301 ниже и проверьте HTTPS. Пара NS индивидуальна: выдумывать или копировать её из чужой инструкции нельзя. Сам перенос DNS не переносит регистрацию и продление домена из REG.RU.

## Зеркало .online → .ru: именно 301

DNS/CNAME сам по себе **не делает HTTP-редирект**. В GitHub Pages у проекта один основной custom domain, поэтому для `.online` используйте URL forwarding регистратора с HTTPS или отдельный сервис редиректов. Нужен сертификат и на `.online`: иначе пользователь не дойдёт до редиректа по HTTPS.

### Cloudflare Redirect Rule

Если зона `.online` обслуживается в Cloudflare, включите проксирование DNS и создайте Single Redirect:

- Условие: hostname равен `soberoctober.online` или `www.soberoctober.online`.
- Dynamic target: `concat("https://soberoctober.ru", http.request.uri.path)`.
- Status code: **301**.
- Preserve query string: **включено**.

Не делайте правило на `.ru` в обратную сторону. После настройки проверьте обе схемы HTTP/HTTPS и вложенные пути:

```sh
curl -I "https://soberoctober.online/calculator/?utm_source=test"
# HTTP ... 301
# Location: https://soberoctober.ru/calculator/?utm_source=test
```

Документация: [Cloudflare Single Redirects](https://developers.cloudflare.com/rules/url-forwarding/single-redirects/).

### Альтернативы

- **Caddy/VPS:** готовый `deploy/Caddyfile`. Указать `dist` как web root, направить DNS всех доменов на сервер. Caddy выдаёт TLS-сертификаты; `.online` возвращает 301 с сохранением пути и query. Запустить и проверить конфигурацию в своей инфраструктуре.
- **Netlify:** скопировать `deploy/netlify.toml` в корень, подключить GitHub-репозиторий, добавить оба домена и TLS. Сборка `npm run build`, папка `dist`; не задавать `BASE_PATH` и `NOINDEX`. В конфигурации есть host-specific 301. Проверить сохранение query на фактическом хостинге.
- **Другой статический хостинг:** загрузить `dist`, включить directory indexes, custom 404 и HTTP 301 для зеркала на уровне CDN/веб-сервера.

## Проверка в браузере

- Мобильная ширина 360/390 px: нет горизонтальной прокрутки, поля и кнопки доступны.
- CTA → калькулятор: изменения чисел меняют прогноз; невалидные значения не сохраняются.
- Старт сегодня/в прошлом/в будущем; 5 октября → 4 ноября; явное подтверждение прошлых дней.
- Отметить/снять дату и обновить страницу: состояние сохраняется, будущие даты неактивны.
- Собрать строку Bingo, обновить страницу, снять клетку: статус линии меняется.
- Скачать PNG после первой отметки: 1080×1350, реальные отмеченные дни, приблизительные ₽/ккал.
- Изменить настройки без потери отметок при той же дате; сменить старт; отменить/подтвердить удаление.
- Cookie: отказ, отдельные переключатели, отзыв; без реальных ID внешних запросов нет.
- Прямые URL статей, клавиатура, Escape/фокус в диалогах, неизвестный URL → 404.

Медицинские формулировки опираются на NHS и NIAAA; ссылки есть в статьях. Не добавляйте обещания «восстановления за N дней», схемы самостоятельной отмены при зависимости или оценку «безопасной дозы».

## Версия «Свои 31»: адвент, цели и радости

- `/anytime/` — круглогодичный вход, дата старта остаётся произвольной.
- `/advent/` — все 31 оригинальные карточки в статическом HTML для чтения и индексации.
- `/calendar/` — карточка дня, необязательная цель, реальные пятничные советы, недельные итоги, подарки на 7/14/21/31 дни, экспорт напоминания `.ics`.
- `/wall/` — личный дневник (до 100 записей в браузере) и общая стена с предварительной модерацией.
- `/wall-rules/` — правила, сроки хранения, приватное обращение к модератору.

Цель и открытые карточки хранятся отдельно в `sober-journey:v1`. Старый прогресс v1 миграции не требует. Сброс календаря не удаляет дневник; у дневника своя кнопка удаления. Номер дня зависит от даты, а расчёты — от отмеченных дней. Пропуск не закрывает материалы. `.ics` содержит нейтральное название «Пять минут для себя» и повторение до конца челленджа; поддержка уведомлений зависит от приложения календаря.

### Реклама и партнёрские бонусы

В календаре один блок РСЯ расположен после ежедневного полезного блока; на главной и в статьях остаётся по одному блоку. До настройки ID и согласия посетителя реклама скрыта. Контейнер резервирует высоту, но фактический формат нужно проверить после подключения РСЯ. Ни публикация записи, ни открытие подарка не требуют клика по рекламе.

`partnerOffers` в `public/config.js` принимает только согласованные предложения: `day`, `title`, `terms`, `region`, `starts`, `expires`, `url`, необязательный `code`, обязательный `label` с согласованной маркировкой рекламы. Сейчас массив пуст: вымышленных скидок нет. Истёкшее или ещё не начавшееся предложение не показывается. Бесплатные редакционные подарки работают независимо от партнёров. Дата на устройстве не защищает ценные одноразовые промокоды — их должен выдавать партнёр или отдельный сервер.

### Аналитика без содержимого дневника

После согласия на Метрику доступны события `advent_open`, `joy_saved`, `wall_submitted`. Все три JavaScript-цели созданы в счётчике 113532359 с точным совпадением идентификатора. Не передаются тексты, цель участия, параметры напитков, дата старта, отметки и сообщения модератору. `advent_open` — первое открытие карточки в этом браузере, а не доказательство выполнения задания.

### Что проверить перед запуском на soberoctober.ru

1. Подключить домен, HTTPS и редирект `.online` с сохранением пути; проверить инструкции выше.
2. Переключить `SITE_DOMAIN` в GitHub на `soberoctober.ru`, убедиться, что `NOINDEX` выключен для основного домена. GitHub-предпросмотр остаётся с `noindex`.
3. Яндекс Вебмастер подключён, sitemap отправлен. Проверить результаты обхода после выпуска HTTPS; Google Search Console пока не подключён. Проверить реальные ответы 200/404 и выбранный canonical.
4. Метрика подключена и согласие проверено. Указать публичный контакт владельца; для рекламы получить ID РСЯ и пройти модерацию площадки. РСЯ пока отключена.
5. Для публичной стены проверить отправку → приватную очередь → одобрение → отображение → скрытие. Назначить человека, который просматривает очередь. Личный дневник не зависит от доступности сервера.
6. Проверить предложения партнёров перед добавлением. Частотность запросов в Wordstat пока не исследована: названия страниц — содержательная структура, а не подтверждённая оценка спроса.

## Сервис общей стены

Исходники `wall-worker/` предназначены для Cloudflare Workers + D1; основной сайт продолжает работать на статическом хостинге. Проверка Turnstile, лимит 10 отправок в день на временный хеш IP, ограничение длины, серверная валидация, приватная очередь, ручное одобрение/скрытие. В публичном ответе только одобренные тексты, ID и дата. Сырые IP в нашей базе не сохраняются. Секреты не должны попадать в GitHub или `public/config.js`.

Из каталога `wall-worker`:

```sh
npx wrangler@4 login --use-keyring
npx wrangler@4 d1 create soberoctober-wall
# Вставить полученный database_id в wrangler.jsonc
npx wrangler@4 d1 execute soberoctober-wall --remote --file=schema.sql
npx wrangler@4 secret put TURNSTILE_SECRET
npx wrangler@4 secret put MODERATOR_TOKEN
npx wrangler@4 deploy
```

`MODERATOR_TOKEN` — случайный секрет не короче 32 символов. Вводить интерактивно, не указывать в командной строке. Создать Turnstile widget для `soberoctober.ru` и `pr0kopenko.github.io`, action `wall` выставляется приложением. В `public/config.js` добавить только публичные `wallApi` и `turnstileSiteKey`. Список `ALLOWED_ORIGINS` в Worker должен точно совпадать с origins сайта; подкаталог `/soberoctober` в origin не входит.

Модерация: открыть `<wallApi>/admin`, ввести ключ (он хранится только в памяти вкладки), выбрать очередь, нажать «Опубликовать» или «Отклонить / скрыть». Обращения об удалении появляются там же. Неодобренные тексты и обращения очищаются через 30 дней, опубликованные через год, хеши лимитов через два дня; ежедневная очистка запускается cron. Ограничения бесплатного тарифа и доступность Cloudflare проверяйте для вашей аудитории перед запуском.

Официальные инструкции: [D1](https://developers.cloudflare.com/d1/get-started/), [Turnstile](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).

### Модерация на этом компьютере без копирования ключа

При настройке ключ сохранён в системном хранилище Windows (`soberoctober` / `wall-moderator`). Дважды нажмите `Модерация.cmd` в папке проекта, затем откройте `http://127.0.0.1:4783`. Локальный помощник передаёт ключ только нашему сервису стены; ключ не попадает в браузер или GitHub. Для остановки закройте окно помощника. Нужны Node.js и установленный глобально `@napi-rs/keyring@1.3.0`. На другом компьютере используйте обычный вход `<wallApi>/admin` и собственную безопасную передачу ключа; он не переносится вместе с репозиторием.
