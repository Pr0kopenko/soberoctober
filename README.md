# Sober October

Русский mobile-first сайт про 31 день без алкоголя. Калькулятор, личный календарь, Bingo 5×5, скачиваемая PNG-карточка и материалы без обещаний медицинских эффектов.

**Основной адрес:** https://soberoctober.ru  
**Репозиторий:** https://github.com/Pr0kopenko/soberoctober  
**Предпросмотр:** https://pr0kopenko.github.io/soberoctober/

## Стек и стоимость

Статический HTML + CSS + ES modules. Node.js нужен только для сборки и локального запуска. Никаких npm-зависимостей, обязательного backend, базы данных, внешних шрифтов или платных API. React/Next.js здесь не нужны: все страницы заранее отрисованы для SEO, взаимодействия небольшие и работают на устройстве. Готовую папку `dist` можно разместить на любом статическом хостинге. Условия бесплатных тарифов хостингов могут меняться.

## Запустить локально

Нужен Node.js 22+ (CI использует 24). Установка зависимостей не требуется.

```sh
git clone https://github.com/Pr0kopenko/soberoctober.git
cd soberoctober
npm run dev
```

Открыть http://127.0.0.1:4173. После правки исходников повторить `npm run build` и обновить страницу; сервер `npm run preview` обслуживает готовую сборку без пересборки. Остановка — Ctrl+C. Не открывайте HTML через `file://`: модули и localStorage требуют обычного HTTP-сайта.

```sh
npm test
npm run build
npm run check
npm run preview
```

`npm test` проверяет формулы, границы дат, високосный год, валидацию хранилища, подсчёт отметок и линии Bingo. `npm run check` проверяет все страницы, локальные ссылки и ресурсы, JSON-LD, метаданные, H1, sitemap и размер OpenGraph-картинки.

## Как считается прогресс

Номер дня — место сегодняшней даты в 31-дневном календаре. Итоги и карточки используют **только подтверждённые пользователем даты**, включая сегодня, если он отметил этот день. Это количество дней, не непрерывная серия. Пропуски не стирают достижения.

Дата старта включается в 31 день: 5 октября → 4 ноября. Можно выбрать прошлое или будущее. При старте задним числом можно явно подтвердить все прошлые дни; по умолчанию флажок выключен. Будущие даты нельзя отмечать. После 31 дня итоги остаются доступны.

Формула: `вечеров в неделю × порций за вечер × отмеченных дней / 7`. Деньги — умножение на цену порции. Калории — умножение на объём / 100 и ккал на 100 мл. Прогноз калькулятора использует 31 день. Оценки усреднённые, без расходов на замену и без прогноза веса. Калорийность по умолчанию — редактируемое допущение, предпочтительны данные с упаковки.

Изменение чисел пересчитывает старые отметки. Изменение даты старта сбрасывает календарь, но сохраняет Bingo; интерфейс предупреждает об этом. Удаление всех данных требует подтверждения в диалоге.

## Хранение и приватность

Ключи: `sober-october:v1`, `sober-bingo:v1`, `sober-consent:v1`. Персональные параметры не уходят в API и не передаются в Метрику. Резервной копии и синхронизации нет: другой браузер, другой домен или очистка хранилища — другой прогресс. В частности, отметки с GitHub Pages автоматически не перейдут на `.ru`.

При запрете localStorage появляется сообщение, а форма не переходит на календарь, пока данные нельзя сохранить. Повреждённый или несовместимый JSON игнорируется. PNG создаётся локально в Canvas, без сервисов генерации и сетевых загрузок. Web Share используется только при поддержке браузером, скачивание PNG остаётся доступно.

## Публикация через GitHub Pages

1. В репозитории открыть **Settings → Pages → Source: GitHub Actions**.
2. Push в `main` запускает тесты, сборку, проверку ссылок и публикацию. Для pull request выполняется проверка без деплоя.
3. Пока домен не подключён, сайт работает в `/soberoctober/` на GitHub Pages. Такой предпросмотр помечен `noindex`, а `robots.txt` запрещает индексацию; canonical и OpenGraph заранее указывают на основной `.ru`.
4. Свою инструкцию ниже выполните после настройки DNS: нельзя считать домены подключёнными только потому, что репозиторий опубликован.

Документация: [GitHub Pages и Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Основной домен soberoctober.ru

1. Верифицировать домен в настройках GitHub Pages аккаунта через предложенную TXT-запись. Не удалять её после проверки.
2. В DNS регистратора настроить apex `.ru` на GitHub Pages по [актуальной инструкции GitHub](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Использовать адреса из документации на момент настройки; не переносить случайные IP из старых руководств. Для `www` — CNAME на `pr0kopenko.github.io`, если нужен этот алиас.
3. В **Settings → Pages → Custom domain** указать `soberoctober.ru`, дождаться проверки DNS и сертификата. Включить **Enforce HTTPS**, когда станет доступно.
4. В **Settings → Secrets and variables → Actions → Variables** добавить `SITE_DOMAIN=soberoctober.ru`. Это публичная настройка, не секрет.
5. Повторно запустить workflow. Сборка переключится на `/`, добавит `CNAME`, снимет `noindex` и разрешит индексацию.
6. Проверить HTTPS, прямой вход на `/calculator/`, скачивание карточки, canonical, `/robots.txt`, `/sitemap.xml` и `/og.png`. Добавить sitemap в Яндекс Вебмастер и другие нужные поисковые системы.

Не включайте `.ru` в переменной до подключения домена: сборка с корневыми путями не предназначена для предпросмотра в `/soberoctober/`.

## Зеркало .online → .ru: именно 301

DNS/CNAME сам по себе **не делает HTTP-редирект**. В GitHub Pages у проекта один основной custom domain, поэтому для `.online` используйте URL forwarding регистратора с HTTPS или отдельный сервис редиректов. Нужен сертификат и на `.online`: иначе пользователь не дойдёт до редиректа по HTTPS.

### Cloudflare Redirect Rule

Если зона `.online` обслуживается в Cloudflare, включите проксирование DNS и создайте Single Redirect:

- Условие: hostname равен `soberoctober.online` или `www.soberoctober.online`.
- Dynamic target: `concat("https://soberoctober.ru", http.request.uri.path)`.
- Status code: **301**.
- Preserve query string: **включено**.

Не делайте правило на `.ru` в обратную сторону. После настройки проверьте обе схемы HTTP/HTTPS и вложенные пути:

```sh
curl -I "https://soberoctober.online/calculator/?utm_source=test"
# HTTP ... 301
# Location: https://soberoctober.ru/calculator/?utm_source=test
```

Документация: [Cloudflare Single Redirects](https://developers.cloudflare.com/rules/url-forwarding/single-redirects/).

### Альтернативы

- **Caddy/VPS:** готовый `deploy/Caddyfile`. Указать `dist` как web root, направить DNS всех доменов на сервер. Caddy выдаёт TLS-сертификаты; `.online` возвращает 301 с сохранением пути и query. Запустить и проверить конфигурацию в своей инфраструктуре.
- **Netlify:** скопировать `deploy/netlify.toml` в корень, подключить GitHub-репозиторий, добавить оба домена и TLS. Сборка `npm run build`, папка `dist`; не задавать `BASE_PATH` и `NOINDEX`. В конфигурации есть host-specific 301. Проверить сохранение query на фактическом хостинге.
- **Другой статический хостинг:** загрузить `dist`, включить directory indexes, custom 404 и HTTP 301 для зеркала на уровне CDN/веб-сервера.

## Яндекс Метрика

1. Создать счётчик для `soberoctober.ru`.
2. В `public/config.js` задать `metricaId: 'ЧИСЛОВОЙ_ID'`, пересобрать и сделать push.
3. Счётчик загружается только после согласия на аналитику. Отказ и отзыв согласия доступны внизу каждой страницы.
4. Вебвизор, карта кликов и отправка значений форм отключены. Не добавляйте в цели тип напитка, стоимость, дату старта или отметки пользователя.
5. В браузере проверить отсутствие запросов к `mc.yandex.ru` до согласия и их появление после согласия. Блокировщики могут мешать проверке.

Подключение сверено с [инициализацией Метрики](https://yandex.ru/support/metrica/ru/code/counter-initialize). Вставлять второй независимый счётчик поверх предусмотренного кода не нужно.

## РСЯ

1. Добавить основной сайт в РСЯ, подтвердить владение и пройти модерацию. Доход и одобрение не гарантированы.
2. Создать адаптивный RTB-блок. Задать его реальный `R-A-…-…` в `public/config.js` как `rsyaBlockId`.
3. Заменить комментарий в `public/ads.txt` на **точные строки из своего кабинета**. В проекте нет выдуманных seller ID.
4. Пересобрать и опубликовать. Реклама появится только при согласии на рекламную категорию и приближении к месту размещения.
5. На главной и статье предусмотрено максимум одно место после основного контента. В калькуляторе, календаре и юридических страницах рекламы нет. Без ID/согласия блок не занимает место.

Документация: [блоки РСЯ](https://yandex.ru/support/partner/en/web/units/), [ads.txt](https://yandex.ru/support/partner/ru/web/ads-txt-setup). Настройки блока и требования площадки проверяйте в своём кабинете перед включением.

## Перед включением внешних сервисов

Страницы privacy/cookies описывают фактическое техническое поведение этого MVP. Добавьте данные владельца и рабочий контакт, уточните условия вашего хостинга и обработки данных; при изменении интеграций актуализируйте тексты. `contactEmail` в конфиге может содержать публичный контакт. Не помещайте в репозиторий токены, пароли или секретные настройки.

## Проверка в браузере

- Мобильная ширина 360/390 px: нет горизонтальной прокрутки, поля и кнопки доступны.
- CTA → калькулятор: изменения чисел меняют прогноз; невалидные значения не сохраняются.
- Старт сегодня/в прошлом/в будущем; 5 октября → 4 ноября; явное подтверждение прошлых дней.
- Отметить/снять дату и обновить страницу: состояние сохраняется, будущие даты неактивны.
- Собрать строку Bingo, обновить страницу, снять клетку: статус линии меняется.
- Скачать PNG после первой отметки: 1080×1350, реальные отмеченные дни, приблизительные ₽/ккал.
- Изменить настройки без потери отметок при той же дате; сменить старт; отменить/подтвердить удаление.
- Cookie: отказ, отдельные переключатели, отзыв; без реальных ID внешних запросов нет.
- Прямые URL статей, клавиатура, Escape/фокус в диалогах, неизвестный URL → 404.

Медицинские формулировки опираются на NHS и NIAAA; ссылки есть в статьях. Не добавляйте обещания «восстановления за N дней», схемы самостоятельной отмены при зависимости или оценку «безопасной дозы».
