# Автоматическое обновление сайта на REG.RU

Исходники остаются в GitHub. Workflow `.github/workflows/reg-hosting.yml` собирает сайт в GitHub Actions и передаёт только содержимое `dist` через explicit FTPS (порт 21), с проверкой сертификата и шифрованием данных. Поддержку FTPS на конкретном сервере необходимо подтвердить первой публикацией. SSH и установка Node.js на хостинге не требуются.

## Подготовка

1. Создать сайт `soberoctober.ru` в панели хостинга с псевдонимом `www.soberoctober.ru`. Записать его корневой каталог. Не менять DNS до проверки загруженного сайта.
2. В GitHub Settings → Secrets and variables → Actions добавить секреты `REG_FTP_HOST`, `REG_FTP_USER`, `REG_FTP_PASSWORD`, `REG_FTP_ROOT`. Значения берутся из панели хостинга; пароль не публикуется в коде, отчётах или чате. `REG_FTP_ROOT` должен указывать на отдельный уже существующий каталог сайта, доступный FTP-пользователю, а не `/`.
3. При необходимости настроить environment `reg-hosting` с ручным одобрением публикации.
4. Запустить Actions → Publish to REG hosting → Run workflow. Проверить успешную публикацию и сайт на новом сервере до переключения DNS.
5. После проверки включить repository variable `REG_DEPLOY_ENABLED=true`: коммиты в `main` будут автоматически публиковаться. До этого запуск выполняется только вручную.

## Переключение

Сохранить старые DNS-записи для отката. Настроить основной домен и www на проверенный адрес хостинга; убрать www CNAME GitHub. Согласовать CAA с фактически выбранным удостоверяющим центром. Выпустить доверенный сертификат для обоих имён, затем включить редиректы HTTP → HTTPS и www → основной домен. Проверить все четыре адреса, страницы, ресурсы и отправку записи на общую стену. GitHub Pages остаётся резервной публикацией до завершения проверки.

## Ограничения

Файлы загружаются через временное имя и переименовываются по одному; главная страница обновляется последней. Это не атомарная замена всего сайта. Посторонние и устаревшие файлы автоматически не удаляются. `CNAME` предназначен для GitHub Pages и на REG.RU не передаётся. Данные общей стены и локального трекера этим процессом не изменяются.

Подготовленный workflow сам по себе не означает завершённый перенос: нужны доступ, первая успешная загрузка, проверка сайта и HTTPS.
